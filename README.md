# 多智能体智能办公汇报系统

本项目用于软件体系结构课程实验。三名成员使用开源框架搭建多智能体系统，完成办公汇报任务，并提交记录环境搭建、协作运行和运行截图的实验报告。

当前已建立 M1 最小 Python 工程、模型适配器与连通验证脚本；五角色、业务数据工具、编排和界面尚未实现。真实模型验证状态见 [M1 实施记录](docs/M1实施记录.md)，不能用替身测试代替真实实验结果。

## 1 项目方案

采用 Python、LangGraph 和 Streamlit，在本地运行一个具有五种角色的协作系统：

**需求协调 Manager → 大纲规划 Planner → 数据整理 Data → 报告撰写 Writer → 审核 Checker**

Checker 发现问题后，编排层根据问题类型返回对应角色处理；达到返工上限后交由人工检查。通过审核的业务汇报以 Markdown 文件导出。

三个成员共同开发五个 Agent，每个 Agent 都有独立的角色指令、输入输出和运行记录。组员人数、Agent 数量和模型数量分别计算；五个 Agent 可以使用同一个模型。

## 4 三人分工

| 成员 | 主责 | 联调责任 |
| --- | --- | --- |
| A 组长 | Manager、LangGraph 编排、统一状态、运行日志 | 接口整合、异常处理、部署说明 |
| B | Planner、Data、本地数据工具、样例数据 | 数据口径、来源追溯、预期结果核对 |
| C | Writer、Checker、Streamlit 界面、Markdown 导出 | 审核返工、结果展示、截图整理 |

三人共同完成集成测试、课程实验报告和架构分析；各自填写个人贡献与总结。成员姓名、设备和模型尚待实施时记录。

## 5 完成条件

后续实现应同时达到以下条件：

1. 在记录清楚的环境中启动界面，完成一次真实模型连通验证。
2. 五个 Agent 能独立验证，并通过结构化结果和明确的交接记录协作。
3. 完成技术部汇报、行政部满意度汇报两个正常场景，以及缺少数据、审核返工、模型调用失败等异常场景。
4. 数值来自本地数据工具，报告中的结构化指标能追溯到输入文件和计算口径。
5. 保留真实运行日志、原始截图、输出文件和三人贡献记录，完成课程实验报告。

使用替身模型的自动测试只能验证程序逻辑；最终实验验收必须包含 `live` 模式的真实调用。具体测试编号和截图编号见[实验实施计划](docs/实验实施计划.md)。

## 6 后续实施顺序

先完成 M1 环境与模型协议验证，再确认业务数据协议，进入单 Agent、五角色主流程、审核返工、界面和证据整理。具体模型、依赖版本、耗时及费用以实际记录为准。

### 6.1 安装最小工程

使用 Python 3.11，在项目根目录执行：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pip install --no-deps -e .
office-verify --environment
python -m pytest
```

依赖已固定在 `requirements.txt` 和 `requirements-dev.txt`，后者包含运行依赖和 pytest。已有 `.venv` 时直接激活；无需重新创建。本机安装与验证情况见实施记录，其他成员设备仍需复现。

### 6.2 配置 OpenCode Go

仅在尚无 `.env` 时复制示例：

```bash
cp -n .env.example .env
```

在本机编辑 `.env` 的 `MODEL_API_KEY`，不要将密钥发到聊天、写入命令行或截图。Shell 中同名环境变量优先于 `.env`。

默认模型为 `deepseek-v4.1-flash`，接口根地址为 `https://opencode.ai/inference/go/openai/v1`；模型名与可用性以 [OpenCode Go 官方文档](https://opencode.ai/docs/go/)及账号实际权限为准。API 中使用裸模型 ID，不加 OpenCode 客户端的 `opencode-go/` 前缀。官方文档说明 DeepSeek 需工作区允许 Global 区域；如果返回 403，应先检查密钥与权限，不自动切换模型。

```bash
office-verify --live
```

该命令最多发起四次真实请求，按顺序验证：文本回复、JSON mode 输出并经 Pydantic 校验、模型自主选择工具及工具结果回传。工具只计算合成输入 `[3, 5]`，回传的随机标记用于确认模型确实读取了程序结果，不读取办公资料。任一步失败即停止，不自动重试或切换为替身响应。

原始记录保存在本机 `evidence/raw/<run_id>/` 的 `manifest.json`、`events.jsonl` 和 `summary.json`。日志不保存密钥或模型内部推理内容；未知用量为 `null`，费用记为未核算。成功退出码为 0，验证失败为 1，配置错误为 2。Go 主要面向编码 Agent，本批次探针使用代码测试请求；后续办公任务的服务适用性仍待确认。

尚无 `app.py` 或可启动的业务界面。原始[实验指导书](软件体系结构（研究生）实验指导书：基于OpenClaw的多AI%20Agent智能办公协作系统开发.docx)保留在项目根目录。
