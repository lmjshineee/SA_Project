## 11 体系结构分析

围绕实际实现和运行证据展开分析，避免仅列框架功能。若老师仍要求独立不少于 2000 字的架构分析报告，可据本节扩写并单独提交；具体要求另行核对。

1. **架构与职责**：为什么分为五个角色；模型、工具、编排、界面之间如何划分；有什么耦合和单点。
2. **协作与状态**：共享状态和交接消息的作用；为何采用串行；数据更新后如何使旧草稿失效。
3. **审核和可靠性**：确定性规则与语义审核分别覆盖什么；返工有什么收益和成本；实际仍会遗漏什么。
4. **可扩展性**：新增一种指标、一个角色或更换模型，实际需要改哪些组件；区分已经验证与仅提出的方案。
5. **安全性**：资料快照、路径限制、密钥配置、模型输出校验如何实现；有哪些部署范围限制。
6. **传统 MAS 比较**：比较决策机制、通信协议、状态管理和可验证性。避免将规划、工具或分布式能力说成 LLM Agent 独有，涉及具体框架时引用其原始资料。
7. **改进方向**：根据实际问题提出有依据的下一步，不把尚未实现的并行、恢复或检索能力写入已完成功能。
